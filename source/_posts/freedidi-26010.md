就在今天，AI 圈又迎来了两款备受关注的重磅模型！一个是万众期待的 **Qwen4（通义千问 4）**，另一个则是 Claude 最新旗舰模型 **Fable 5.2**。

两款模型相继登场后，迅速引发了大量讨论。尤其是 Claude Fable 5.2，在正式发布前后的各种测试中，已经展现出令人惊讶的代码生成和复杂任务执行能力。从零制作 3A 游戏、设计电子设备，到开发具有完整交互功能的应用，AI 的开发能力似乎又迈上了一个新台阶。

![](/images/freedidi-26010/img01.webp)

那么，作为国产新一代模型的 Qwen4，面对 Claude Fable 5.2 又能有怎样的表现？两款模型究竟谁更胜一筹？

这次我们将使用相同的提示词，通过实际项目进行对比测试，看看它们在代码编写、游戏开发、逻辑推理以及复杂任务执行方面的真实表现。

## 一、Qwen4-Max 与 Claude Fable 5.2 正式登场

首先来看看 Qwen4。

目前正式推出的是 **Qwen4-Max**，需要通过 API 接口进行调用。大家期待的开源 27B 版本以及 Flash 轻量化版本，预计也将陆续推出。

这意味着，即使暂时没有开源模型，我们也可以先通过 API 体验 Qwen4-Max 的实际能力。

另一边，Claude Fable 5.2 同样备受关注。根据目前公开的测试案例，它在复杂代码生成、游戏开发和多步骤任务执行方面展现出了非常强的实力。

尤其是一些开发者分享的项目，已经不再局限于简单的网页和代码片段，而是直接尝试从零构建完整的游戏和交互式应用。

## 二、Claude Fable 5.2 的实际能力有多强？

在正式进行我们的对比测试之前，先看看社区中已经出现的一些令人印象深刻的案例。

### 1. 一次性提示词，从零制作完整游戏

有开发者尝试使用一次性提示词，在不需要人工反馈的情况下，让 Fable 5.2 从零开始制作一款完整游戏。

整个项目没有使用现成的模型、音效和纹理素材，全部由 AI 自行生成和实现。

根据开发者分享的数据，整个项目耗时约 8 小时，生成了约 270 万个输出 Token，输入约 4.45 亿个 Token（大量使用缓存），按照 API 定价估算，成本约为 550 美元。

这也说明，模型虽然能够完成复杂项目，但高强度开发任务的 Token 消耗和成本同样不容忽视。

**提示词如下：**

```
你是一名顶级3D游戏开发工程师，请使用 HTML5 + Three.js + JavaScript + Web Audio API，开发一款具有3A级视觉效果的第一人称3D射击游戏。

## 一、核心要求

游戏名称：SHOTGUN APOCALYPSE

游戏题材：末日丧尸生存射击。

游戏视角：第一人称 FPS。

核心武器：霰弹枪，包括泵动式、半自动和双管霰弹枪。

**最重要：最终游戏必须是一个完整的、可直接运行的 index.html 单文件。**

所有 HTML、CSS、JavaScript、游戏逻辑、UI 和音效代码全部整合在一个 HTML 文件中，不允许拆分成其他文件，不需要后端和本地编译。允许通过 CDN 加载 Three.js，但需要说明网络依赖。

## 二、画面品质

追求高品质3A游戏视觉效果，而不是简单的 Three.js 演示。

- 写实风格的3D废弃城市场景。
- 精细建筑、汽车、集装箱和环境模型。
- 高品质材质、动态光照、阴影和雾效。
- 枪口火焰、烟雾、弹壳和粒子特效。
- 精致的第一人称持枪视角。
- 流畅的镜头运动和动画。

场景必须具有真实的空间层次和丰富细节。

## 三、霰弹枪系统（核心重点）

至少实现三种可切换霰弹枪：

- 泵动式霰弹枪。
- 半自动霰弹枪。
- 双管霰弹枪。

每把枪拥有独立模型、射击动画、后坐力、伤害、射速和弹药容量。

必须实现真实的射击体验：
- 枪口火焰和烟雾。
- 弹壳抛出。
- 枪械后坐力和镜头震动。
- 动态准星。
- 弹丸散布和命中检测。
- 泵动、装填和换弹动画。
- 不同武器独立的射击节奏。

## 四、音效系统（强制要求）

必须有完整的游戏音效，不能出现无声射击。

使用 Web Audio API 程序化生成或组合合法授权音效。

包括：
- 霰弹枪开火声。
- 泵动上膛声。
- 装填和弹壳掉落声。
- 脚步声。
- 丧尸嘶吼和攻击声。
- 子弹命中声。
- 环境风声和背景音乐。
- UI按钮交互音效。

支持主音量、音乐音量和音效音量调节。

首次点击开始游戏时初始化音频系统，确保浏览器不会阻止声音播放。

## 五、敌人与游戏玩法

设计多种3D丧尸敌人，包括普通丧尸、快速丧尸和重型丧尸。

敌人必须能够：
- 自动巡逻。
- 发现并追踪玩家。
- 接近玩家并发动攻击。
- 受到枪击后产生受击反馈。
- 死亡并播放动画。

采用波次生存模式，敌人逐波增加，玩家通过击杀获得积分和补给，最终挑战Boss。

## 六、UI设计（重点）

采用现代军事科技风格，深色背景、半透明面板、橙色和红色点缀。

必须有精美的：
- 游戏主菜单。
- 开始游戏按钮。
- 游戏设置。
- 生命值和护甲显示。
- 武器及弹药显示。
- 动态准星。
- 波次和击杀统计。
- 暂停菜单。
- 游戏胜利和失败结算界面。

所有按钮必须具有真实功能和交互动画，不能只是装饰。

## 七、操作方式

WASD：移动
Shift：冲刺
Space：跳跃
鼠标：控制视角
鼠标左键：射击
鼠标右键：瞄准
R：换弹
1、2、3：切换武器
ESC：暂停

支持鼠标 Pointer Lock。

## 八、最终交付与测试

请直接开发，不要只输出设计方案或代码示例。

必须完成：
1. 完整的3D游戏场景。
2. 可正常使用的枪械和射击系统。
3. 完整音效。
4. 敌人AI和波次系统。
5. 精美UI。
6. 完整游戏开始、暂停、失败和重新开始流程。

实际检查游戏运行情况，修复JavaScript错误、交互问题和音效问题。

最终只交付一个完整的 index.html 文件，可以直接在 Windows 11 浏览器中打开运行。

**开发优先级：游戏画面品质 > 霰弹枪射击手感 > 音效质量 > UI精美程度 > 其他玩法功能。**

不要为了追求功能数量而降低核心体验品质。不要使用大量简单几何体敷衍画面。请优先把有限的开发资源集中在第一人称枪械模型、射击动画、枪声、场景光影和UI设计上。宁可功能少一些，也要保证实际游戏体验和视觉品质。
```

### 3. 设计完整的电子设备

其中包括一个家庭语音助手中心。

这类任务已经不只是简单的 UI 设计，而是需要模型理解产品需求、设计结构，并实现相应的功能。

### 5. 仅用 4 个 Prompt，制作接近 AAA 级别的赛车游戏？

另一个非常引人关注的案例，是使用 Fable 5.2 制作赛车游戏。根据开发者分享，整个项目只使用了 4 个 Prompt，开发时间约 8 小时，基于 Unity 引擎完成。

赛道、车辆、光影以及游戏场景均由模型生成，没有使用外部素材。

从最终展示的效果来看，已经具备相当不错的游戏质感。

当然，这并不意味着 AI 已经能够完全取代专业游戏开发团队，但它所展现出的开发效率和潜力，确实值得关注。

### 6. 将实体手帐制作成 3D 电子手帐

除了游戏开发，Fable 5.2 在精细化交互设计方面也有不错的表现。有开发者将一本实体手帐制作成了 3D 电子版本。

为了获得更好的效果，开发过程中采用了不同模型配合的方式：先使用 Opus 5.5 搭建基础结构并完成交互功能，随后切换到 Fable 5.2，对照实际拍摄的视频进一步优化材质和结构。

![](/images/freedidi-26010/img09.webp)

最终实现了透明咖啡色软壳、不锈钢活页、拖动翻页、点击日期直接记录，以及 90 枚可以撕取和粘贴的贴纸等功能。

甚至还加入了摇晃手帐时触发铃铛音效的交互。

这种对材质细节和交互体验的还原能力，确实让人眼前一亮。

## 四、使用 LocModel 对接 API，实测两大模型

看完这些案例，相信大家最关心的还是：如果让两款模型使用完全相同的提示词，它们最终生成的结果究竟有什么区别？

这次我们使用 **LocModel** 作为测试工具，分别接入 Qwen4-Max 和 Claude Fable 5.2。

当然，你也可以使用其他支持自定义 API 的 Agent 软件进行测试，整体思路都是一样的。

首先，我们需要准备好对应模型的 API Key，然后进入 LocModel 的设置中心，添加 API 配置信息。完成 API 配置后，就可以分别选择对应模型进行调用。

## 五、总结：AI 编程能力又一次迎来升级

从目前公开的案例来看，Claude Fable 5.2 已经展现出了非常强的复杂项目开发能力，尤其是在游戏制作、交互设计和视觉细节方面，令人印象深刻。

而 Qwen4-Max 的表现同样值得期待，特别是后续即将推出的开源 27B 和 Flash 版本，如果能够兼顾模型能力、运行成本和本地部署需求，将会给开发者带来更多选择。

至于这场 Qwen4 与 Claude Fable 5.2 的正面对决，究竟谁的实际表现更好，还是需要通过相同提示词、相同任务的实际测试来判断。

AI 编程的发展速度越来越快，过去需要专业开发团队花费大量时间才能完成的项目，现在已经可以尝试交给 AI 独立完成。
